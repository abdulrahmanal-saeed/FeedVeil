# FeedVeil — الخطة التنفيذية الكاملة (بالعربي)
**تاريخ التوثيق:** 22 نوفمبر 2026  
**الحالة الحالية:** تخطيط فقط — لم يتم إنشاء مشروع أندرويد أو APK بعد.

## 1. هدفنا
بناء تطبيق أندرويد مستقل يُثبَّت بجانب **تطبيق Facebook الأصلي**، ويراقب العلامات الظاهرة للإعلانات المموّلة أثناء التصفح عبر صلاحية Accessibility. الهدف **تقليل الإعلانات قدر الإمكان** دون Root، ودون إنشاء متصفح بديل، ودون تعديل تطبيق Facebook نفسه.

**مهم:** نظام أندرويد لا يسمح للتطبيقات العادية بحذف عناصر واجهة Facebook الداخلية. وبعض الإعلانات قد لا تظهر علاماتها داخل شجرة عناصر Accessibility. لذلك لن نضمن منع 100% من الإعلانات، ولن نفعّل التمرير التلقائي إذا لم نستطع التمييز الموثوق بين الإعلان والمنشور العادي.

## 2. المميزات الأربع المتفق عليها
| الميزة | الفكرة | شروط التشغيل |
| --- | --- | --- |
| **Auto Skip** | تمرير محسوب لتجاوز المنشور المموّل المؤكّد | بعد إثبات دقة الاكتشاف ومنع التمرير الخطأ؛ مغلق افتراضيًا |
| **Hide Ad** | فتح قائمة المنشور واختيار إخفاء الإعلان من خيارات Facebook | فقط لو ظهر الخيار الصحيح وتأكدنا منه؛ قد يغيّر تفضيلات الحساب؛ موافقة منفصلة |
| **Visual Mask** | وضع طبقة مؤقتة فوق مساحة الإعلان | لا يزيل المساحة من الصفحة؛ يختفي فور التمرير/الخروج/الشك في الموضع |
| **Manual Assist** | عرض زر بسيط يساعد المستخدم يتخطى الإعلان بنفسه | لا ينفّذ حركة إلا بضغط المستخدم؛ الحل البديل إذا كان الحجب التلقائي غير موثوق |

مع المميزات الإضافية: واجهة عربي/إنجليزي، عداد للإعلانات المكتشفة والمتخطاة **بأرقام منفصلة**، وضع قراءة فقط، زر إيقاف شامل، وقواعد اكتشاف قابلة للاختبار والتحديث بإصدارات واضحة.

## 3. طريقة عمل التطبيق
1. المستخدم يشغّل FeedVeil ويقرأ شرح صلاحية Accessibility ويوافق بإرادته.
2. يفتح Facebook الأصلي. الخدمة تعمل في نطاق **com.facebook.katana** فقط.
3. عند تغيّر عناصر الشاشة، نقرأ **بيانات الواجهة الضرورية فقط** مثل الوصف، النصوص ذات الصلة والحدود الهندسية؛ دون حفظ نصوص منشورات أو أسماء حسابات.
4. محرك الاكتشاف يحاول تحديد علامات «ممول» / Sponsored في **سياق المنشور نفسه**؛ ويصنّف النتيجة إلى: إعلان مؤكد / منشور عادي / غير معروف.
5. لو النتيجة «غير معروف»، التطبيق **لا يتدخل**. ولو إعلان مؤكد، يختار **إجراء واحد فقط** حسب الخيارات المفعلة وإجراءات الأمان.
6. أي تغيير في التطبيق الأمامي، سحب من المستخدم، شاشة غير معروفة، مشكلة، أو ضغط زر الإيقاف يؤدي لإيقاف التدخل وإزالة الطبقات المؤقتة.

## 4. الأدوات والهيكل
- Kotlin + Jetpack Compose + Material 3.
- AccessibilityService و AccessibilityNodeInfo وAndroid accessibility actions.
- قواعد اكتشاف محلية Rule-Based قابلة للاختبار؛ **لا AI ولا Backend ضروريان في البداية**.
- DataStore للإعدادات والإحصائيات المجمعة، واختبارات JUnit واختبارات أندرويد الفعلية.
- GitHub Actions لبناء Debug APK وتشغيل الاختبارات (نجاح البناء لا يساوي نجاح الحجب على Facebook).
- بدون VPN أو Root أو LSPosed أو تحليل اتصالات Facebook أو طلب كلمة مرور الحساب.

## 5. مراحل التطوير

### Phase 0 — اختبار الجدوى (الأولوية الأولى)
- إنشاء مشروع أندرويد أصغر ما يمكن وخدمة Accessibility **للقراءة فقط**.
- اختبار هل تظهر علامة Sponsored / ممول في شجرة الواجهة مع Facebook الأصلي فعلًا.
- مقارنة النتائج يدويًا بين إعلان عادي ومنشور عادي في واجهة عربية وإنجليزية.
- إخراج APK تجريبي وتقرير: أمثلة الإشارات القابلة للاكتشاف، الإعلانات التي لا نستطيع اكتشافها، ومخاطر التخطي.
- **ممنوع أي ضغط أو تمرير تلقائي في هذه المرحلة**.
- نقطة القرار: هل نستطيع تحديد منشور إعلاني واحد بدقة كافية أم نكتفي بالمساعدة اليدوية؟

### Phase 1 — محرك اكتشاف الإعلانات
- بناء قواعد اكتشاف مع نتيجة AD / NORMAL / UNKNOWN.
- ربط علامة الإعلان بحاوية المنشور؛ وعدم الاكتفاء بوجود كلمة «ممول» في أي نص.
- اختبار التكرار والتمرير السريع وتغييرات اللغة والإصدارات.
- توفير عداد محلي دون تخزين المحتوى الشخصي.
- لا نفعّل أي تصرف تلقائي إلا إذا اجتاز الاختبارات.

### Phase 2 — Manual Assist
- إنشاء زر صغير قابل للإغلاق داخل Facebook أثناء ظهور إعلان موثوق.
- الضغط عليه ينفذ تخطيًا واحدًا؛ والإلغاء يعني عدم تنفيذ شيء.
- دعم اتجاه اليمين لليسار، وتفادي حجب أزرار Facebook.

### Phase 3 — Auto Skip
- اختيار حاوية تمرير صحيحة، وتحديد حركة محدودة، والتحقق من تغير الشاشة بعدها.
- حماية ضد التمرير المتكرر، أو تخطي منشورات الأصدقاء، أو التداخل مع لمس المستخدم.
- مفتاح تشغيل منفصل ومغلق افتراضيًا حتى يجتاز الاختبارات.

### Phase 4 — Hide Ad
- التأكد هل قائمة Facebook تعرض خيار **إخفاء الإعلان** وهل يمكن الوصول إليه بطريقة موثوقة.
- عدم الخلط بين إخفاء الإعلان، إخفاء المنشور، والإبلاغ.
- تحذير وموافقة منفصلة لأن الإخفاء قد يعدّل تفضيلات Facebook.
- لو القائمة غير واضحة، نتوقف من غير أي ضغط تخميني.

### Phase 5 — Visual Mask
- تحديد حدود الإعلان على الشاشة وعرض طبقة يمكن حذفها بسهولة.
- إزالتها فور تغيير الشاشة أو التمرير أو تعطيل الخدمة.
- التأكد أنها لا تغطي أدوات تسجيل الدخول أو الصفحات الأخرى.
- **الطبقة لا تحذف مساحة الإعلان من واجهة Facebook الأصلية**.

### Phase 6 — صقل التطبيق وإصدار APK
- واجهة عربي وإنجليزي، إعدادات، إحصائيات، زر إيقاف، اختبارات أداء وبطارية.
- اختبارات مع تحديثات Facebook ومقاسات الشاشة والوضع الليلي.
- بناء APK موقّع بإدارة صاحب المشروع للمفاتيح، وتوثيق المميزات المدعومة فعلًا.
- مراجعة سياسة التوزيع قبل مشاركة التطبيق مع أي مستخدمين آخرين.

**Reels / Stories / إعلانات الفيديو** أبحاث مستقبلية منفصلة، لأن واجهاتها قد لا تسمح بنفس طريقة اكتشاف إعلانات المنشورات.

## 6. معايير الجودة المقترحة (أهداف، مش نتائج فعلية)
- دقة اكتشاف الإعلان ضمن الحالات المصنفة إعلان: **98% أو أعلى** بعينة موثقة.
- تغطية **70% على الأقل من الإعلانات التي تظهر علامتها فعلًا في Accessibility** (وسيتم قياس تغطية جميع الإعلانات بشكل مستقل).
- أخطاء تخطي المنشورات العادية بسبب Auto Skip: **أقل من 1%** في الاختبارات، ومنع أي أخطاء خطيرة في التنقل.
- اختيار قائمة Facebook الخاطئة: **صفر** في مجموعة الاختبار؛ أي خطأ يعطّل الميزة.
- الطبقة البصرية لا تبقى بعد الخروج/الإيقاف: **صفر حالات**.
- عدم إرسال أو تخزين المحتوى الشخصي: شرط ثابت.
- أي عينة صغيرة لا تكفي لإثبات النجاح = إبقاء الأتمتة مغلقة.

## 7. الخصوصية والتوزيع
- الصلاحية حساسة؛ نعرض وظيفتها وحدودها قبل فتح إعدادات النظام، ويقدر المستخدم يرفض أو يوقف الخدمة.
- لا تخزين لأسماء الحسابات أو الصور أو رسائل/نصوص المنشورات، ولا إرسال بيانات Facebook للسيرفر.
- **الريبو حاليًا Public**: ممنوع رفع صور شاشة خاصة، سجلات خام، مفاتيح توقيع أو أسرار.
- سياسة Google Play تمنع تطبيقات تتدخل في إعلانات تطبيقات أخرى؛ لذلك **لن نفترض إمكانية النشر على Google Play** بهذه الوظيفة. البداية هي APK للاستخدام الشخصي مع مراجعة شروط التوزيع.
- التطبيق مستقل وغير تابع لـMeta/Facebook.

## 8. قواعد إدارة المشروع
- تنفيذ كل مرحلة في Branch وPull Request منفصلين مع اختبارات ومعايير قبول.
- توثيق الاختبارات الحقيقية، ولا نضع أرقام نجاح تخمينية.
- عدم دمج أي ميزة تلقائية قبل الموافقة على نتيجة الاختبارات.
- إذا غيّر تحديث Facebook واجهته، نوقف المميزات غير المتوافقة حتى إعادة التحقق.
